# 增加一种桌面区域

自由桌面的区域属于本插件，不是 eNest 的主题槽位或第三方小组件协议。扩展随插件源码一起构建，不加载安装目录之外的 HTML、脚本、URL 或其他插件的窗口。

1. 在 `src/regions.js` 加入一个稳定的 `kind`、显示名称和 `fields()`。框选结束菜单和工具栏「＋ 区域」都从这张表生成。`fields()` 只返回允许持久化的 JSON 字段，校验类型和长度；不要保存绝对路径、实例句柄、HTML 或回调。
2. `src/model.js` 负责通用 `id / screen / rect`、屏幕失联回退和区域数量限制。需要用户编辑的新字段，在 `change()` 增加具体动作和归属校验。`src/persistence.js` 将一次变更的区域记录和索引放在同一个私有 KV 事务中，不能绕过它独立覆盖布局。
3. 在 `public/assets/vendor/desk/surface.js` 的 `card()` 添加渲染分支，样式放在相邻的 `surface.css`。普通工作区和托管桌面共用这套视图。使用 DOM 文本/属性，不拼 HTML。对数据库、网络、文件等昂贵能力应有显式入口，空白桌面不触发扫描或申请权限。
4. 交互通过 `src/studio.js` 的受限动作处理器。若桌面层也需要操作，显式登记 `backend/session.mjs` 和工作区的 helper 动作白名单，附会话、来源屏和当前区域校验。需要选择文件、应用或新权限时，仅通过「打开工作区」返回，再由用户在可见窗口中操作。私有管道不暴露 Node、宿主 API、搜索结果、路径或执行脚本的方法。
5. 已授权目录只观察直接子项，离开工作区且未接管时停止监听；显式接管持有的后台活动、原生窗口和句柄必须在退出、禁用、卸载或父进程断连时释放。实现新区域时保持这种可撤销性。
