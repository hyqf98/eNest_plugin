# 双入口工具插件验收

本文件原始验收范围是 `eNest/eNest_plugin/plugins` 中 13 个业务插件。数据库、SSH、hello 与 theme-demo 不在范围内。每个插件自行设计 Quick 与桌面布局，共享部分仅负责主题、宿主操作、设置与状态桥接。

## 自动检查

所有命令从插件仓库根目录运行。浏览器测试使用 Playwright 驱动系统 Chrome（macOS 优先 `/Applications/Google Chrome.app`），没有安装系统 Chrome 的环境需要先安装 Playwright Chromium。

| 命令 | 覆盖内容 |
| --- | --- |
| `npm run build:tools` | 使用统一构建器自动发现全部插件；共享 npm 包随各插件编译 |
| `npm run test:tools` | 跨平台入口，运行下列 13 插件双模式浏览器检查 |
| `node --test scripts/tests/utility-tools.test.mjs` | 科学计算优先级/错误、时区与 DST、严格编解码、JSON 大整数与路径差异、随机密码与 UUID 位、二维码模板/SVG |
| `UTILITY_UI=1 node --test scripts/tests/utility-tools.test.mjs` | 六个工具的实际 DOM 操作、复制/导出调用、JSON 树/diff、二维码生成后识别、双向入口迁移 |
| `DUAL_MODE_UI=1 node --test scripts/tests/dual-mode-tools.spec.mjs` | 13 插件 × 4 模式/宽度组合；浅深主题 token、低/中/高动画档、草稿迁移、7 类持久状态重新载入、功能入口与横向溢出 |
| `node scripts/validate-manifests.mjs` | 插件 manifest、权限与声明式设置格式 |

统一浏览器测试现在读取每个插件的 `dist/`，在生产 CSP 下执行。`@enest/plugin-kit` 由 Vite 编译进 `assets/app/`，没有共享目录回退或 `assets/shared` 副本。先执行 `npm run build`；指定部分项目时使用 `node scripts/build-plugin.mjs <id...>`。

截图输出到 `/tmp/enest-dual-mode-smoke/<插件>-quick.png` 与 `*-shell.png`，共 26 张。测试以 760×520 的 Quick 内容区、1200×760 的桌面内容区为基线；另检查 Quick 1100×760 和桌面 480×760 的功能入口及横向边界。通过不重载页面双向发送模式变更、只缩放宽度不变更模式，检验布局由真实 `mode` 驱动。

## 验证边界

浏览器检查使用模拟 `window.enest`。存储模拟器通过 localStorage 保留宿主 KV 数据，并在重新加载后检查恢复；这证明插件调用与状态恢复逻辑，不能替代真实 Electron 磁盘存储验证。

截图/录屏/贴图、系统剪贴板回贴、辅助功能授权、操作系统保存对话框、Quick 原生窗口焦点和 WebContentsView 移动，需要另行在 Electron 中验证。浏览器的快捷键检查覆盖 PluginKit 的返回、聚焦、编辑器上 Ctrl+Enter 请求固定到桌面，不宣称已经验证主进程对 Ctrl/Cmd+Enter 的拦截。

主题测试注入与宿主相同类别的 CSS token 和 `data-anim`，检查背景色与低/中/高档动效；二维码输出画布白底是二维码图片本身的配置，不跟随界面深色主题反转。

## 真实 Electron 与系统验证（2026-10-13）

壳仓库的 `src/main/plugin/pluginTools.native.test.mjs` 从 13 份 `.enestplugin` 归档解包到全新的临时数据根，使用生产 preload 和原生 WebContentsView。执行 `ENEST_TOOLS_NATIVE=1 node --test src/main/plugin/pluginTools.native.test.mjs`：

- 13 个包均成功加载，Quick → 桌面 → Quick 保持相同 WebContents，模式事件和 DOM 一致。
- 顶部输入查询/动作及 generation、声明式设置默认值/更新、附件跨插件隔离均通过。
- 番茄钟关闭后仍运行，再打开恢复真实后台状态。
- 当前 macOS 屏幕权限已允许；实测 160×100 截图、区域取消、贴图关闭与约 1.7 秒 WebM 录屏，验证文件头和非空输出。没有把浏览器模拟结果当作原生能力验收。

实际验收修复了辅助沙盒窗口不支持 ESM preload，以及录制页 data: 地址没有 mediaDevices 的问题：三个辅助 preload 现在是独立 CJS，录制页经临时 file: 文档加载，保留 sandbox/contextIsolation。

`native/clipboard/tests/mac.integration.test.mjs` 另外通过真实文件剪贴板、原窗口恢复、实际粘贴与失效目标降级；测试使用专用 Cocoa 窗口并恢复原剪贴板，不向用户文档输入。macOS 不提供可靠的公开剪贴板来源 API，因此来源为未知。

Linux 已完成 Xvfb 和私有 D-Bus portal 协议验收，包括 INCR 大文件列表、窗口失效、授权成功/拒绝/取消/撤销，ASan/UBSan 无错误。**Windows 实机、Linux 桌面会话（GNOME/KDE、X11/Wayland）仍未在本机完成实测**；Wayland 因无可靠原窗口恢复接口，按设计返回复制后手动粘贴。详情在壳仓库 `native/clipboard/README.md` 和 `LINUX.md`。

Linux ARM64 的依赖打包也已隔离验收：helper 携带 19 个非 glibc 共享库，每个库使用相对 RUNPATH；带库产物通过上述 Xvfb / portal 回归。它在未额外安装任何库或 CLI 的 Debian 12 runtime 中正常运行固定 JSON 协议，runtime 的系统包清单与原始基础镜像完全相同。发布构建需使用匹配架构的 Linux builder；当前验证基线为 glibc 2.36，不包含更旧 glibc、musl 或 Linux x64 实机验收。最终用户无需另装 xclip、xdotool、wl-copy、json-glib 或 XTest。
