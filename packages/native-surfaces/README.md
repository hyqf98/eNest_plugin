# Native Surfaces

Plugin-owned region selection, pinned-image presentation and MediaRecorder policy. Import `createNativeSurfaces(host)` to obtain an inherited facade with `screen.capture/selectRegion/record` and `pin.open/close/list/closeAll`. The original preload is never mutated. Only `screen.capture` and `screen.displays` are native host capture primitives; region geometry, image zoom and recording state live here.

Add `nativeSurfacesAssets()` from `@enest/native-surfaces/vite` to the plugin's Vite config. Its awaited `configResolved` hook materializes this package's `assets/` into `public/assets/vendor/native-surfaces/` for both dev and build; Vite includes them at `assets/vendor/native-surfaces/` in the distribution. Generated public copies are ignored; real source files (not symlinks) preserve the host's restricted source-preview contract. The assets run in sandboxed auxiliary windows with `window.enestAux` only. They cannot access the owner's full API, settings, filesystem or clipboard. The owner page receives opaque `auxiliary.message` events and performs ordered private-file writes itself.

Recording starts from a real click on the auxiliary page. The host binds `getDisplayMedia` to one granted display, one main frame and one current plugin generation. No synthetic activation, arbitrary capture ID or camera/microphone permission is supplied. After capture starts, the owner hides the auxiliary page; stop/cancel remains in the plugin. Pending capture confirmation is bounded to 120 seconds. The screen assistant stops, drains and persists its history during the host's existing bounded close grace; disposal or permission revocation stops capture and discards unfinished output. A slow/full disk or forced termination can exceed the grace deadline and is not reported as successful saving.

There is no Node backend process. Active auxiliary windows and private output streams hold bounded runtime activities; opening no surface allocates no window or interval. MediaRecorder and native disk queues are bounded, writes are acknowledged and serialized, and partial output is discarded on failure/cancellation. Existing saved recordings and screenshot history are not rewritten. Private outputs allow two streams per owner, 512 KiB chunks, 16 pending writes, 8 MiB queued bytes, 1 GiB per output and 4 GiB owner storage. Uninstall clears only that owner's private output directory. UUID partial files left by a crashed process are reclaimed on the next open, not interpreted as recorded history.

The host permits eight simultaneous auxiliary windows per owner and 24 globally. Ephemeral Electron Sessions use stable plugin-private slots, with a per-open nonce and owner/main-frame checks. Slots cannot be reused until old handlers are detached and storage cleanup settles. Long image data URLs are converted to compressed Blob URLs and discarded; window teardown clears image/video/canvas references and capture tracks. Ordinary auxiliary windows are a basic UI capability. Native capture still requires `screen.capture`/`screen.record` and OS consent; non-capture `alwaysOnTop` uses the legacy `pin.create` permission name for generic desktop placement, not a host-owned image feature.

Requires eNest >= 0.2.3. Native multi-display/media/permission and visible button interaction need actual-app verification; mock tests alone are not UI acceptance.
